# Вход и регистрация: что доработать на бэкенде

Вёрстка всех экранов из Фигмы (секция «Регистрация и вход») готова в `login.html` и `kz/login.html`.
Фронт работает через слой с тремя методами; сейчас локально отвечает заглушка, на проде — текущий вход по телефону.

## Файлы

| Файл | Что внутри |
|---|---|
| `login.html` | Разметка всех экранов: старт (Email/Телефон), код, второй контакт, ИИН, готово |
| `src/lib/main.js` → `initAuth` | Только интерфейс: маска телефона, проверка email/ИИН, таймер, состояния. В API не ходит |
| `src/lib/api.js` → `live()` | Реальные запросы. **Здесь дорабатывать** |
| `src/lib/auth-mock.js` | Заглушка. Включается на `localhost` или с `?mock`, выключается `?live` |

## Сценарий

1. Старт: пользователь выбирает вкладку Email или Телефон, вводит контакт, жмёт «Получить код».
2. Экран кода (6 цифр).
3. Аккаунт есть → вход, редирект на главную.
4. Аккаунта нет → экран «Регистрация»: просим **второй контакт** (вошёл по Email — просим телефон, по телефону — Email) → код на этот контакт.
5. Экран ИИН → «Ваш аккаунт FLEX создан» → «Перейти на сайт».

## Контракт слоя (`live()` в api.js)

Фронт вызывает три метода. Ошибка — `throw { status, code, detail }` (это уже делает функция `api()`).

### `sendCode({ channel, value, purpose })`
- `channel`: `"email"` | `"phone"`; `value`: `"user@mail.com"` или `"+77071234567"`.
- `purpose`: `"login"` — первый экран; `"contact"` — второй контакт при регистрации.
- Ошибки, которые фронт различает:
  - `code: "CONTACT_TAKEN"` (только `purpose: "contact"`) → под полем «Этот Email уже используется» / «Этот номер уже используется».
  - любая другая → плашка «Не удалось отправить код. Попробуйте через 5 минут.»

### `verifyCode({ channel, value, code, purpose })` → `{ next }`
- `next: "done"` — пользователь вошёл (токен сохранён в `localStorage.flex_session`), фронт уходит на главную.
- `next: "contact"` — аккаунта нет, фронт показывает экран второго контакта.
- `next: "iin"` — фронт показывает экран ИИН.
- Ошибки:
  - `code: "OTP_EXPIRED"` → «Срок действия кода истёк» + кнопка «Получить новый код»;
  - `status` 4xx → «Неверный код. Попробуйте ещё раз.»;
  - `status` 5xx / сеть → плашка «Произошла ошибка на сервере».

### `register({ iin })`
- Создаёт аккаунт и сессию. Ошибка → текст под полем ИИН (`detail` или «ИИН введён некорректно»).

## Что уже работает и что нет

| Ветка | Статус |
|---|---|
| Вход по телефону, существующий клиент | ✅ `/cabinet/login/code` → `/cabinet/login/verify` |
| Регистрация по телефону без Email | ✅ `/phone` → `/otp/verify` → `/register` → `/cabinet/session` |
| Вход по Email | ❌ нет эндпоинтов |
| Второй контакт (Email после телефона / телефон после Email) | ❌ нет эндпоинтов |
| `OTP_EXPIRED` отдельно от неверного кода | ❓ проверить, отдаёт ли API такой код |

В `live()` уже прописаны **предполагаемые** пути — их нужно заменить на реальные:

| Вызов в коде | Назначение |
|---|---|
| `POST /email/code { email, purpose, verify_token? }` | Отправить код на почту |
| `POST /email/verify { email, code, verify_token? }` | Проверить код. Для существующего аккаунта вернуть `{ token }`, для нового — `{ verify_token }` |
| `POST /phone { phone, verify_token }` при `purpose: "contact"` | Код на телефон как второй контакт к уже начатой регистрации |
| `POST /otp/verify { phone, code, verify_token }` при `purpose: "contact"` | Подтвердить второй контакт |
| `POST /register { verify_token, iin }` | Должен привязать к аккаунту оба подтверждённых контакта |

## Как включить вход по Email

В `src/lib/api.js`: `const EMAIL_LOGIN = false;` → `true`.
Пока `false`, на проде нет вкладок, и после кода по телефону сразу идёт экран ИИН (как сейчас).
Не забыть поднять `?v=` у `api.js` во всех HTML.

## Заглушка (локальная проверка)

`node server.js` → http://localhost:8080/login (заглушка включена). Боевой режим локально: `/login?live`.

| Ввод | Результат |
|---|---|
| Email начинается с `new`, телефон заканчивается на `00` | Новый пользователь → регистрация |
| Любой другой контакт | Существующий → вход |
| Email начинается с `fail`, телефон на `99` | Ошибка отправки кода |
| Второй контакт: Email с `taken`, телефон на `11` | «уже используется» |
| Код `000000` / `222222` / `500500` | Неверный / истёк / ошибка сервера |
| Любой другой код | Успех |
| ИИН `000000000000` | Ошибка регистрации |

## Превью отдельных экранов без ввода

`/login?state=<экран>-<канал>-<вариант>`:
- `start-email`, `start-email-filled`, `start-email-format`, `start-email-send` (то же с `phone`)
- `code-email`, `code-email-typing|filled|loading|wrong|expired|server` (то же с `phone`)
- `contact-email`, `contact-email-filled`, `contact-email-taken` (то же с `phone`)
- `iin`, `iin-typing`, `iin-filled`, `iin-error`
- `login`, `complete`, `complete-redirect`
